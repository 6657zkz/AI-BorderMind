# 模块契约索引

模块契约面向模块消费者、开发者和 Agent，说明已实现模块的稳定职责、对外接口和依赖边界。它们用于快速定位上下文，但字段级类型、实际行为和可用性以代码与测试为准。

## 状态标记

- `implemented`：有代码和测试证据。
- `planned`：仅存在于架构或路线图；不创建详细伪契约。
- `retired`：禁止恢复的旧模块或接口。
- `test-only`：仅用于测试，不能当作产品能力。

## 标准章节

每个已实现模块契约应包含：

1. 状态与代码入口。
2. 职责与非职责。
3. 公开接口、输入与输出。
4. 关键不变量与错误/恢复语义。
5. 允许依赖、禁止依赖和副作用。
6. 测试证据。
7. 变更规则。

## 已实现模块

- [capabilities](capabilities.md) — `implemented`，按类型组织的静态能力定义、构建期注册和冻结只读目录。
- [planning](planning.md) — `implemented`，纯领域的业务图校验和执行计划编译。

## 变更规则

修改模块公开接口、职责、依赖边界、状态/失败语义时，必须同步更新对应契约和测试。涉及持久化权威来源、公开 API、能力目录所有权、执行语义、权限或 LLM/数据访问边界时，还必须按 [ADR 规则](../adr/README.md) 记录决定。
